# Security review gates

Read `AGENTS.md` and `docs/security.md` first.

1. Check authorization at service/tool execution, not only routing/UI.
2. Filter vector, keyword and document lookup by trusted workspace identity; citations must respect permissions.
3. Treat retrieved text as untrusted; prompt injection cannot grant tools privileges.
4. Sensitive write action lifecycle: propose -> persist immutable pending payload -> explicit user confirmation -> re-authorize -> single idempotent execution -> audit.
5. Avoid raw SQL generated by LLMs, arbitrary URLs or unrestricted MCP permissions.
6. Limit prompt size, model costs, tool counts, timeouts and retry budgets; fail closed on unclear authorization.
7. Use synthetic demo contracts, not genuine confidential agreements.
8. Report findings ranked by severity with affected file/flow, exploit scenario and mitigation; do not pretend an audit is proof of safety.
